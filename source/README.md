## 本轮：分组 cell 与原生滑动兼容

确认 WCRefine 分组页使用 `WCRGroupingNativeSessionCell`，不是首页的
`NewMainFrameCell`。右滑入口现在同时支持已确认的分组控制器表格和普通
`UITableViewCell` 分组行；首页仍只接受 `NewMainFrameCell`。

WCRefine 在分组控制器上接管 `trailingSwipeActionsConfigurationForRowAtIndexPath:`
这一 UIKit 表格接口，因此它负责分组页的动作入口，系统负责收拢和回弹动画。
后续可以沿用该原生容器改善动画，但不会让右滑依赖首页 cell 类。

修复 iPad 分栏布局中分组表格没有被识别为分组页，导致右滑手势未安装。
分组控制器仍是唯一判断依据；现在同时接受控制器视图层级内的嵌套或代理
表格，避免依赖 `tableView` 属性必须与触摸表格对象完全相同。
首页表格和其它未知表格仍不会进入分组右滑路径。

## 1.9.18：等待真实状态，串行处理提醒设置

修复 1.9.17 在 1 秒读回未变化时直接结束确认的问题。
此时显示“同步中”，只在实际状态符合目标后执行回组或发送提升。
移除该路径的 N06 失败提示，不用本地假状态代替微信开关。

- 每次需要写入时只调用一次原生接口，保留一次 1 秒延后读取。
  后续借用当前会话的行刷新或消息事件确认；事件读取间隔至少 0.5 秒，
  每个请求最多 16 次。30 秒后遇到下一个事件时再做最后一次读取，
  仍不能确认则结束等待，提示到微信聊天设置核实。
  这是惰性结束，无新增周期计时器、轮询、全列表扫描或后台唤醒。
- 相反设置等待前一次实际状态确认后才发送，避免旧状态被当成新操作成功；
  最新的同向请求可取消排队的相反操作。等待期间按钮显示“同步中”。
- 等待集合最多 128 个会话；换号清除旧等待项，退出后台或手动保持／回组
  撤销插件后续动作。已发出的原生请求无法由插件撤回。
- 原生状态和界面刷新可能仍受微信版本影响。此修改处理过早判失败及
  重叠请求，不能证明所有群聊设置失败均由这两个原因造成。

## 1.9.17：群聊提醒状态延后确认

用户在分组内对群聊右滑切换免扰／提醒后收到 N06。
该代码表示原生接口已经调用，随后立即读回未确认目标状态；
不能据此判断权限不足，也不能证明微信已完成设置。

- 首次读回仍未变化时，1 秒后只重新读取当前会话一次。
  不重复发送设置请求，不循环重试，不扫描会话列表。
- 状态已经一致或同步完成时立即结束，不安排延后操作。
  同一会话同方向的重复请求合并；反向请求替换旧回调。
  等待集合最多 128 项，满时在写入前提示稍后重试。
- 账号变化、退后台、手动保持或回组均阻止旧回调触发后续动作。
  原生设置请求一旦发出，取消插件回调不能撤销微信自身的在途操作。
- 仅在确认实际状态后回组或将发送成功的会话显示到首页。
  延后仍未确认时保留失败提示，不用本地假状态替代微信设置。
- 注册 113 项原生核心测试，新增延后更新、单次确认、重复合并、
  反向请求、取消、换号、后台、拒绝、容量和重入场景。

### 耗电与兼容性审查结论

旧实现虽无周期轮询，但有“查询 → 每项重新获取 → 状态写入 →
全局分组通知 → 再刷新”的冗余链，不能据“没有轮询”就声称无额外开销。
本轮消除这类由持久化引发的全局刷新，并减少稳定会话的异步观察。
仍然存在以下成本，不能承诺零耗电：

- 主插件原有分组刷新遍历会话时，本插件仍增加少量字段读取和状态比较；
  账号识别、成员索引以及微信私有读取本身也有成本。
- 到期/回主页的重新获取是 O(T)，T 为当前临时跟踪数，不扫描聊天消息历史；
  主插件收到可见性变化后执行自身列表刷新，可能仍有 O(N) 会话处理。
- 期限选择遍历临时活动记录；同时有多项状态改变时，目前仍可能逐项保存账号记录，
  并非整批只落盘一次。稳定状态测试检查不重复写入，不等于能耗实测。
- 多个不同到期时刻可导致多次单次唤醒；未给每会话建立重复定时器。
  启动时原有有限次 UI/接口就绪重试仍保留，并非持续扫描。

兼容性上不改消息数据库、未读数、通知开关或分组成员，不新增消息收发 hook。
保留 WCRefine 真实未读策略回退，设置页仍显示真实开关值。
但为让临时投影进入现有分组谓词，配置 getter 仍需在业务路径中临时返回开启；
这属于有意的运行时行为改动，不可能据静态审查承诺“绝对无冲突”。
给定样本的未读分组收集函数使用自己的静音/折叠选项，
没有发现它读取该被强制开启的 getter；不能将此推广到所有主插件/微信版本。

详细静态证据及设备验证建议见 `../audit/ACTIVITY_REVIEW.md`。

## 源码改动

### 账号与持久化

`WCRAFStateStore.h/.m` 将名单、保持时间和天数合为一个账号记录：

```text
com.local.wcrefine.activefront.account.v2.<当前 wxid>
```

记录含 `schema=2`、`held`、`since` 和 `days`。一次保存同时更新这些字段。
当前账号通过所提供 WCRefine 2.1-9 样本中的
`+[WCRefineHelper wcr_resolveCurrentUserWxidUncached]` 获取。
账号无法确认时禁用状态操作，不使用共享名单兜底。

检测到账号变化或暂时为空时，废弃内存缓存和异步任务，递增账号代次。
UI 行、按钮、延迟弹窗、弹窗回调以及状态刷新携带原账号上下文；
过期上下文不能写入状态或继续分组操作。持久化键永远由捕获的上下文生成，
不拿“刚刚切换到的账号”替换写入目标。

未知 schema、错误容器类型和非法字段不自动覆盖。
正常旧记录仅缺少保持时间时，可以将缺失项补为当前时间；
绝不按暂时为空的分组快照裁剪名单。
保存期间拒绝同步回调中的嵌套写入，并在保存后再次确认账号，
避免持久化通知切号后把旧账号快照装入新账号缓存。
持久化读写异常安全退出；写入异常会禁用当前账号的内存状态，
等待切号或重启重新加载，不再用可能失配的缓存继续清理。
时钟抛异常或返回无效值时，不续期、不提交过期删除。

账号代次取决于本插件实际观察到的账号值变化。没有新增未经验证的微信账号通知，
不能宣称能检测两次查询之间未被观察到的完整 A→B→A 切换。
多线程账号切换、微信内部加载时序仍需要设备验证。

### 过期处理

- 候选包含账号上下文、整体版本、逐联系人版本、保持时间、天数和批次。
- 队列票据不能取走后来批次；重新保持、修改设置、通知失效等撤销旧快照。
- 某个联系人重新被判定有效时，只撤销该联系人的快照，不使同批其他项饥饿。
- 实际提交前通过
  `-[WCRefineGroupDataProvider fulfilledSessionForUsername:fallback:]`
  重新获取会话，明确传 `fallback:nil`，不回退到排队时的旧对象。
- 重新检查用户名、账号、分组、保持时间、设置和最新消息时间。
  获取失败、异常、时间未知/非有限值时保留持久化标记。
- 一批中成功删除第一项不递增整体版本，其他有效项仍可提交；批末统一刷新。

上述方法存在及 ABI 已与给定主插件元数据核对。
“重新获取”仍受微信会话服务自身缓存和对象更新时序限制，不能视为消除了所有消息竞态。
过期策略查询仍按原语义对已过期项执行未读回退；持久化清理由异步提交负责。

### 分组开销与日志

主线程的一轮同步查询可共享自定义分组 ID 和成员并集。
缓存由主队列后续任务清空，也在分组变化通知、本插件分组修改时失效，
并与账号代次绑定。不缓存空的初始分组快照。
成员类型不支持或非主线程时使用原接口查询。
禁用分组仍计入归属判断，保留原语义；选择目标分组的 UI 继续过滤禁用项。

未引入周期定时器。Group 私有日志在默认发布构建中关闭。
没有测量 CPU、掉帧、唤醒率和能耗，不承诺实际省电幅度。

## 旧记录如何处理

旧共享键没有账号归属，**不会自动导入，也不会删除原件**。

新版本长按“保持/回组”按钮，在保持期限中选择“导入旧版保持记录…”，
再确认记录属于当前账号。新导入项从导入时刻开始计时，已有项不续期。
只有当前账号尚无 v2 记录时，才采用合法的旧天数设置。
在确认窗口期间切号，原确认操作失效。

不要因为升级后名单暂时不见，就对不属于该账号的旧名单执行导入。
回退旧二进制只能看到旧共享键；新版本的账号隔离记录不会反向同步到旧键。

## 设备验收清单

- 已分组好友/非免打扰群发送、收到新消息单独显示；免打扰群不自动展开。
- 临时群改免打扰/折叠后不再自动显示；明确手动保持不被静音过滤删除。
- 未读超过缓冲期不回组；在聊天页停留超过缓冲期，返回主页后才开始缓冲。
- 已读后保持主页前台，分别验证 1 / 3 / 5 分钟到期及期间新消息重新计时。
- 临时会话右滑“保持”、保持后右滑“回组”，长期保持期限与阅读缓冲互不混用。
- 未分组会话不自动收回；重启、前后台切换不丢状态；手动回组同秒新消息边界。
- 单账号保持/回组/分组、期限设置与重启持久化。
- 两账号含相同联系人；A→B→A；退出登录与账号未就绪。
- 弹窗打开或延迟动作排队后切号，确认不会影响新账号。
- 入队后新消息、重新保持、更改期限、修改分组或联系人被移出分组。
- 空分组加载、获取会话失败、未知时间时不丢失保存的标记。
- 原未读设置开/关与设置页显示值；群聊与好友边界。
- 左滑原菜单、右滑、长按、快速滚动、复用行、冷启动可见行和 iPad 弹窗。
- 隐根环境签名/注入、崩溃日志和真实 CPU/耗电对比。

同一进程不要同时加载旧版 Group 与新版 `WCRefineGroup.dylib`，
也不要把主插件 `WCRefine.dylib` 当作 Group 文件替换。
